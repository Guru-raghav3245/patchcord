# Activo MTP Tool — Project Plan

Source of truth for requirements: `Activo MTP Tool — v1 Spec.md`.

## Project outline

A free, self-contained, native macOS app for moving files between a Mac and MTP Android devices (Astell&Kern/Activo, Samsung, others). Primary validation target: **Activo CT10** hi-res DAP. macOS has no native MTP; existing tools are paywalled (MacDroid) or flaky on Apple Silicon (Android File Transfer, OpenMTP).

| | |
|---|---|
| Platform | macOS 11+, Apple Silicon (arm64) only |
| Stack | Swift + SwiftUI; libmtp + libusb via thin C/ObjC++ shim |
| Linking | libmtp/libusb bundled as **dynamic** `.dylib`s in `Contents/Frameworks` (LGPL), rpaths fixed with `install_name_tool` |
| Distribution | Ad-hoc signed `.app` in a DMG from own website; no App Store, no notarization |
| Privacy | USB only, no network, no telemetry, no Full Disk Access |

**Non-goals (v1):** Windows/Linux, Wi-Fi transfer, PTP-only devices, App Store, cloud sync/backup, localization.

## Phases

### Phase 0 — Foundations & de-risking
Goal: prove the hardest part (bundled MTP stack talking to the CT10) before building UI.
- [x] Create Xcode project (SwiftUI, arm64; generated by XcodeGen from `project.yml`; target macOS 12 — Xcode 27 floor, spec says 11)
- [x] Build libusb + libmtp for arm64
- [x] Bundle dylibs in `Contents/Frameworks`; fix install names/rpaths with `install_name_tool`
- [x] Bridging header exposing libmtp to Swift (no shim needed yet)
- [x] Spike: open the CT10 and list its storages (`App/MTPProbe.swift`; run headless with `MTPTool --probe`)

**Exit:** a launched `.app` on a clean Mac lists the CT10 with nothing else installed. *(Met on this Mac: lists "Internal storage — 14.2 GB" across repeated launches. Not yet tried on a second, clean Mac.)*

### Phase 1 — Device layer
Goal: reliable device lifecycle.
- [x] Hotplug connect/disconnect detection (no manual refresh): IOKit notifications + debounced rescan
- [~] Multiple devices: user picks the active one (built; **untested — needs a second Android device**)
- [x] Enumerate all storages (internal + microSD) (internal verified; no microSD card available to test)
- [x] Threading model: all libmtp calls on one serial queue, off the main thread
- [x] "Device busy" message naming the app holding the device (`UsbExclusiveOwner`), with Retry

**Exit:** plug/unplug/replug and dual-device scenarios update the UI correctly. *(Plug/unplug/replug verified on the CT10; dual-device pending.)*

### Phase 2 — Browse
Goal: navigate the device.
- [x] Folder navigation across storages (double-click, breadcrumb, Back / ⌘[)
- [x] File list with name, size, type, modified date (sortable `Table`; Kind from `UTType`)
- [x] SwiftUI browser UI (device/storage picker, breadcrumb, list)

**Exit:** can browse the full CT10 tree on both storages. *(CLI listing verified on the CT10: folders list in <0.1 s. GUI check pending; no microSD to test a second storage.)*

### Phase 3 — Transfers
Goal: safe, fast copying, including very large files.
- [x] Device → Mac and Mac → device copy (folders added in Phase 4)
- [x] Drag-and-drop in both directions (drag-out copies, like Finder across volumes)
- [x] Streamed transfers: 500 MB up in 32 s / down in 28 s, peak memory 12–17 MB
- [x] Progress UI with cancel (cancel verified headless both ways; libmtp patched so upload cancel doesn't stall 60 s)
- [x] Dropped-connection handling: downloads go to a hidden temp file, renamed only after a size check; failed uploads delete the partial object (unplug mid-download verified)

**Exit:** multi-hundred-MB DSD file round-trips byte-identical; cancel and mid-transfer unplug both end in a clear, clean state. *(Met: round-trip and cancel verified headless; GUI, drag-and-drop and unplug mid-transfer verified on the CT10; no permission prompts.)*

### Phase 4 — File management
Goal: manage files on the device.
- [x] Create folder
- [x] Rename (files and folders)
- [x] Delete files/folders (with confirmation; folders deleted depth-first)
- [x] Folder copy in both directions (hidden files skipped on upload)
- [x] ⌘-drag out to move (deletes from device only after a verified download)

**Exit:** operations persist on the device and the UI reflects them. *(Met: verified headless and in the GUI on the CT10.)*

### Phase 5 — Hardening & validation
Goal: confidence beyond the happy path.
- [~] CT10 matrix:
  - [x] 500 MB files, 200-file folders (upload 12 s, download 3 s), nested folders: all byte-identical
  - [x] 20 open/close cycles in a row
  - [x] Unplug mid-download and mid-upload (clear error, no partial file left, device comes back)
  - [x] Real large FLAC upload
  - [ ] Untested: real DSD files, Mac sleep/wake, other USB port, CT10 screen-off during a transfer, replug in under 1 s
  - [ ] Second storage (no microSD available)
- [ ] Secondary check on a generic Android phone (user will have one later; see CLAUDE.md reminder)
- [x] LGPL compliance: dynamic linking; licences, NOTICE and our libmtp patch bundled in `Resources/Licenses`, credited in About; swapping a dylib and re-signing verified
- [x] No network: no networking symbols in any binary, no sockets at runtime; no permission prompts (user-verified)
- [x] Leaks: 0 across list/transfer/create/delete; fixed a libmtp rename leak (in the patch)

**Exit:** matrix passes; no known data-loss bugs. *(No known data-loss bugs. Untested items above are carried forward.)*

### Phase 6 — Packaging & release
Goal: shippable download.
- [x] Ad-hoc signed Release build (`CODE_SIGN_INJECT_BASE_ENTITLEMENTS: NO` so it ships without `get-task-allow`); version 1.0, 1.4 MB
- [x] DMG with drag-to-Applications: `scripts/make-dmg.sh` (hdiutil), 672 KB → `dist/`
- [x] Install note (`Read Me First.txt`): macOS 15+ removed right-click → Open for unsigned apps, so it uses Privacy & Security → Open Anyway
- [x] Install test: app from the DMG runs with the build's libraries hidden (only bundled dylibs load). A real Safari download went through warning → Open Anyway → launch exactly as the read-me says, and later launches have no prompts. Not tried on a second Mac.
- [ ] Publish to website: all four files in `dist/` (DMG, `libusb-1.0.30.tar.bz2`, `libmtp-1.1.23-mtptool.tar.gz`, `SHA256SUMS.txt`). LGPL needs the two source archives next to the DMG.

**Exit:** a fresh Mac can install and use the app from the website download alone. *(Met on this Mac via a real browser download; publishing is the user's step.)*

## Risks & open questions
- macOS or another app (Android File Transfer, MacDroid) may hold the USB interface (seen in Phase 0: `UsbExclusiveOwner`, claim fails with -3; killing them can leave the device needing a replug) — need a clear "device busy" message.
- libmtp quirks on the CT10: one found and patched in Phase 0 (USB reset on close wedges the device; `vendor/patches/libmtp-ct10.patch`). Consider upstreaming. More may surface in Phase 5.
- Intel support: undecided (arm64 only for v1).
- Crash reporting: undecided (no telemetry in v1).
